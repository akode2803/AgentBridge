## Independent review correction

The first live client recorded only `StorageApiError` for expected failures.
Independent review correctly found that a transient 429/5xx or unrelated 400
would have satisfied that classifier. The exact five-second Storage request
window was therefore queried from unified logs before accepting the evidence.
The retained sanitized log rows establish the concrete server outcomes:

- reader before publication: `404 NoSuchKey`;
- create-only repeat: `409 KeyAlreadyExists`;
- attempted upsert: `403 AccessDenied`;
- attempted move: `404 NoSuchKey`;
- exact cleanup: HTTP 200.

The client now accepts only the corresponding public Storage response
status/code pair for each operation, returns that pair as sanitized evidence,
and rejects 429, 5xx, unrelated 400 and generic Storage exceptions. Ten pure
regressions cover the classifier. Because the generated passwords were
destroyed immediately after the first live run, the tightened client itself was
not rerun against those accounts; the time-bounded server logs close the
original evidence ambiguity, while a future run will directly emit the same
structured pairs.
